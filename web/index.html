Activity is evidence.
It is not a verdict.

A quiet release history can belong to stable software. A busy one can include automated prereleases. Neither tells you whether a package is secure or right for your project.

Where the information comes from

The npm Registry supplies version records, dist-tags, maintainer names and declared dependencies. “Latest” means the publisher’s latest dist-tag, which can differ from the newest publication. Unpublished versions may be absent.

jsDelivr supplies CDN request counts for the selected package and returned dates. Requests are not npm installations or unique users. Usage usually arrives with a delay; a missing report is not zero usage.

Captures, privacy and refreshes

The initial records are real dated captures shipped with this page. Use Look up live for current metadata; the page never silently substitutes a saved capture for a failed live lookup. Receipts are downloaded only when you choose. Results remain in this tab unless you download them. Installed-version watchlists stay temporary unless you explicitly save them in this browser. Saved watchlists have no background polling or account sync. The visitor counter receives no package or installed-version fields.

Live lookups go directly from your browser to npm and jsDelivr.

Make it your own

Change web/config.json to set default packages, as many example shortcuts as you need, request limits and timeline length. All public package names remain searchable. Run the repository’s refresh workflow to update retained defaults; normal visitor lookups need no source edit, account or key.
